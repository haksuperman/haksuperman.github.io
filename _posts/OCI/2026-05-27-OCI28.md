# 1. 개요
## 1.1. 프로비저닝 방식
1. 동적 프로비저닝
   1. **새로운 스토리지 클래스(StorageClass)를 정의한 후, 생성한 스토리지 클래스 기반으로 새 PVC를 생성하는 방식**
   2. PVC를 생성할 때 CSI Volume Plugin이 **OCI 내에 새로운 File Storage와 이를 백엔드로 하는 PV를 동적으로 자동 생성**
   3. 기존 Mount Target 활용(OCID 지정)하거나, 새 Mount Target 생성 가능
2. 정적 프로비저닝
   1. **OCI Console에서 수동으로 File Storage와 Mount Target을 미리 생성해 두는 방식**
   2. 미리 생성한 File Storage를 백엔드로 하는 PV를 정의하고, 새로운 PVC를 정의하여 PVC와 기존 File Storage를 가리키는 PV를 바인딩

> 정적 프로비저닝 주의 사항
> - CSI Volume Plugin(`fss.csi.oraclecloud.com`)을 사용하여 OKE 클러스터와 OCI File Storage를 연결
> - 동적 프로비저닝과 달리, K8s 리소스(PV, PVC)를 삭제해도 OCI Console에 생성해 둔 실제 File Storage 및 데이터는 삭제되지 않고 유지됨
> - 기존에 사용 중이던 파일 시스템의 데이터를 K8s 파드에서 이어서 사용하거나, 인프라 관리자와 K8s 관리자의 역할을 분리해야 할 때 적합

## 1.2. 데이터 암호화

- 저장 데이터 암호화 (Data At Rest)
  - 기본적으로 'Oracle 관리형 암호화 키'를 통해 암호화 수행
  - OCI Vault 서비스에서 직접 관리하는 ‘고객 관리형 마스터 암호화 키’를 지정하여 적용 가능

- 전송 중 데이터 암호화 (Data In Transit)
  - 필요 시 선택하여 활성화 가능
  - TLS 1.2 암호화를 적용하여 인스턴스와 마운트된 File Storage 간 전송되는 데이터 암호화 가능
  - Worker Node의 OS가 Oracle Linux 7 혹은 Oracle Linux 8이어야 함

# 4. PV
## 4.1. YAML 정의 파일(매니페스트) 작성

```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: oke-fss-static-pv
spec:
  capacity:
    storage: 50Gi   # FSS는 사용량 기반이므로 명목상 입력값
  volumeMode: Filesystem
  accessModes:
    - ReadWriteMany   # 다중 노드 동시 접근 허용
  persistentVolumeReclaimPolicy: Retain   # 미리 생성한 FSS이므로, Retain 권장
  csi:
    driver: fss.csi.oraclecloud.com
    # <FileSystemOCID>:<MountTargetIP>:<ExportPath>
    volumeHandle: ocid1.filesystem.oc1.ap_seoul_1.aaaaaaaaaanqsp5qnaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa2mia:10.250.4.65:/oke-FSS_ExportPath01
```

# 5. PVC

## 5.1. YAML 정의 파일(매니페스트) 작성
- 생성한 PV를 사용하기 위한 클레임(PVC) 생성
- 동적 프로비저닝이 발생하지 않고 지정한 PV에 정확히 바인딩되도록 지정  
  (storageClassName 항목에 빈 값(““)을 입력해야 함)

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: oke-fss-static-pvc
spec:
  accessModes:
    - ReadWriteMany
  storageClassName: ""   # 동적 프로비저닝 방지
  volumeName: oke-fss-static-pv   # 2단계에서 생성한 PV 이름 지정
  resources:
    requests:
      storage: 50Gi   # PV의 capacity와 일치해야 함
```

![image](/assets/img/posts/OCI/OCI28_08.png)

> spec.storageClassname 항목에 빈 값을 지정하지 않으면, Default storageClass가 사용되어 Pending 상태로 오류가 발생한다.
>
> ![image](/assets/img/posts/OCI/OCI28_09.png)
{: .prompt-warning }

# 6. Pod
## 6.1. YAML 정의 파일(매니페스트) 작성

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx
spec:
  containers:
    - name: app-container
      image: docker.io/library/nginx:latest
      volumeMounts:
        - name: fss-volume
          mountPath: /usr/share/nginx/html    # Nginx 웹 루트에 마운트
  volumes:
    - name: fss-volume
      persistentVolumeClaim:
        claimName: oke-fss-static-pvc    # 위에서 생성한 PVC 이름
```
