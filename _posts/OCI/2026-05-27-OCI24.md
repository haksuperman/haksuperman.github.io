# 1. 기본 개념

- PV(Persistent Volume)는 Kubernetes 클러스터에서 사용하는 영구 스토리지 리소스를 의미한다.
- 파드(Pod)의 생명주기와 분리되어 데이터를 지속적으로 유지할 수 있도록 설계된 객체이다.
- 일반적으로 컨테이너의 파일시스템은 일시적(Ephemeral)이기 때문에 **파드가 삭제되거나 재생성되면 데이터가 함께 사라진다.**  
  -> PV를 사용해 **외부 스토리지에 데이터를 저장함으로써 이러한 문제를 해결할 수 있다.**

# 2. PV 스토리지

## 2.1. 유형

- OCI Block Volume
  - 고성능 블록 스토리지로, 일반적으로 단일 노드에 연결되어 사용하는 방식(ReadWriteOnce0에 적합하다.
  - 데이터베이스, 단일 인스턴스 애플리케이션, 상태 저장 워크로드에 주로 사용된다.

- OCI File Storage
  - NFS 기반의 공유 파일 스토리지로, 여러 노드에서 동시에 접근 가능한 ReadWriteMany를 지원한다.
  - 다중 파드가 동일 데이터를 공유해야 하는 애플리케이션, 파일 공유 환경, 분석/AI 워크로드 등에 적합하다.

## 2.2. 구성 흐름

### 2.2.1. OCI Block Volume

1. StorageClass 정의
   1. CSI 기반 Block Volume용 StorageClass(e.g. oci-bv)를 사용하거나 사용자 정의 StorageClass 생성
   2. 성능(VPU), 복제 정책 등 파라미터 지정 가능

2. PVC(PersistentVolumeClaim) 생성
   1. 사용자가 요청 용량, 접근 모드(ReadWriteOnce 등), storageClassName 지정
   2. Kubernetes가 해당 요청을 감지

3. 동적 프로비저닝 (CSI 동작)
   1. OCI CSI 드라이버가 자동으로 Block Volume 생성
   2. 생성된 볼륨을 PV로 등록 후 PVC와 바인딩

4. 노드 Attach 및 Mount
   1. 파드가 스케줄링된 노드에 Block Volume을 Attach
   2. 노드 내부에 파일시스템으로 Mount 후 컨테이너에 제공

5. 파드 재시작 시 데이터 유지
   1. 파드가 삭제, 재생성되어도 PVC가 유지되는 한 동일 볼륨 재마운트
   2. 단, 기본적으로 단일 노드 연결(RWO)에 적합

### 2.2.2. OCI File Storage

1. File System 및 Mount Target 준비
   1. OCI에서 File System 생성
   2. VCN 내 Mount Target 구성

2. StorageClass 정의 (FSS CSI)
   1. FSS용 CSI StorageClass 생성
   2. 파일시스템 또는 동적 생성 옵션 지정

3. PVC 생성
   1. 요청 용량 및 접근 모드(ReadWriteMany 가능) 지정
   2. CSI가 필요 시 파일시스템/Export 생성

4. NFS 마운트
   1. 파드가 실행되는 각 노드에서 NFS 방식으로 마운트
   2. 여러 노드/파드에서 동시에 접근 가능

5. 공유 스토리지 운영
   1. 파드 재시작, 노드 변경과 무관하게 동일 파일시스템 사용
   2. 별도의 Attach 과정 없이 네트워크 기반 마운트


> **StorageClass / PV / PVC**
>
> - StorageClass : 스토리지를 어떻게 만들 것인지를 정의 (스토리지를 직접 생성하지는 x)
>
>   - 어떤 스토리지 타입 (Block Volume / File Storage)을 사용할지
>   - 어떤 CSI 드라이버를 사용할지
>   - 성능 옵션 (VPU 등)
>   - 복제 정책
>   - 볼륨 바인딩 방식
> - PV : 클러스터에 존재하는 실제 스토리지 객체
>
>   - 실제 OCI 스토리지와 연결됨
>   - 클러스터 내부 리소스로 등록
>   - 특정 PVC와 1:1로 바인딩
> - PVC : 사용자가 필요한 스토리지를 요청하는 객체
>
>   - 필요한 용량 (50Gi)
>   - 접근 모드 (RWO/RWX)
>   - 사용할 StorageClass\
>
> **<font style="color: #ff5630;">PVC는 Pod와 연결되며, Pod는 PV를 직접 참조하지 않는다. 항상 PVC를 통해서만 스토리지를 사용한다.</font>**

## 1.4. CSI 기반 스토리지 연동 구조

- OKE는 Kubernetes의 표준 인터페이스인 CSI(Container Storage Interface)를 통해 OCI 스토리지 서비스와 연동된다.
- CSI 드라이버는 볼륨 생성, 삭제, 연결(Attach), 마운트, 스냅샷 등의 작업을 자동화하며, 사용자는 StorageClass와 PVC 정의만으로도 동적 프로비저닝을 수행할 수 있다.

## 1.5. 고려사항

- Block Volume은 고성능 단일 노드 중심 워크로드에 적합하고, File Storage는 다중 노드 공유가 필요한 환경에 적합하다.
- OKE에서는 managed node 및 self-managed node 환경에서 영구 스토리지를 사용할 수 있다.  
  단, virtual node 환경에서는 Persistent storage가 지원되지 않는다.
