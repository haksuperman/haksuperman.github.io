## 1. 개요

본 문서는 OCI Identity Domain의 Network perimeters와 Sign-on Policy를 이용하여 OCI Management Console 접근을 특정 IP 또는 CIDR 범위에서만 허용하는 방법을 설명한다.<br>

OCI Management Console 접근은 일반적으로 사용자 이름, 비밀번호, MFA와 같은 인증 요소를 통해 보호된다. 하지만 보안 요구사항에 따라 인증 정보가 올바르더라도 승인된 네트워크에서 접속한 경우에만 Console 로그인을 허용해야 할 수 있다.
- 사무실 고정 Public IP에서만 OCI Console 로그인 허용
- VPN 접속 후 NAT되는 Public IP에서만 OCI Console 로그인 허용
- 보안 운영망 또는 관리망에서만 OCI Console 로그인 허용
- 그 외 외부 네트워크에서는 ID/PW와 MFA가 맞더라도 로그인 차단

## 2. 적용 범위

본 문서는 OCI Management Console 웹 로그인에 대한 IP 기반 접근 제어 구성을 다룬다.
- Network Perimeter 생성 및 허용 IP 등록
- Sign-on Policy Rule에 Network Perimeter 적용
- 허용/비허용 IP에서 로그인 동작 검증

> 아래 내용은 문서의 범위에 포함하지 않는다.
> - OCI CLI, SDK, API 접근 제어
> - IAM Policy 또는 Network Source 기반 접근 제어
> - 애플리케이션별 SSO 접근 제어
>
> CLI, SDK, API 접근은 Console 로그인과 별개로, 별도의 인증 및 권한 체계를 사용하므로 추가적인 보안 설정이 필요하다.
{: .prompt-info }

## 3. 구성 개념
### 3.1. Identity Domain
Identity Domain은 OCI IAM에서 사용자, 그룹, 애플리케이션, 보안 정책, 인증 정책 등을 관리하는 단위이다.
- Network Perimeter와 Sign-on Policy는 Identity Domain 단위로 구성된다.<br>
  -> A Domain에 설정한 Network Perimeter와 Sign-on Policy는 다른 Domain에 적용되지 않음
- 운영 환경에 바로 적용하면 관리자 접근이 차단될 수 있으므로, 본 문서에서는 테스트용 별도 Identity Domain을 생성하여 검증한 후 운영 환경에 적용하는 방식을 권장한다.

### 3.2. Network Perimeter

Network Perimeter는 Identity Domain 로그인 시 사용할 수 있는 IP 주소 또는 IP 범위를 정의하는 네트워크 경계이다.<br>
Network Perimeter에는 아래 여러 형식의 IP 정보를 등록할 수 있다.
- 단일 IP 주소 : 특정 Public IP 하나를 지정<br>
  e.g. 203.0.113.10
- 여러 단일 IP 주소 : 여러 IP를 쉼표로 구분하여 지정<br>
  e.g. 203.0.113.10, 198.51.100.20
- IP 범위 : 시작 IP와 종료 IP 사이의 범위 지정<br>
  e.g. 203.0.113.0-203.0.113.10
- Masked IP Address Range : CIDR 형태의 IP 범위 지정<br>
  e.g. 203.0.113.0/24


### 3.3. Sign-on Policy
Sign-on Policy는 사용자가 Identity Domain 또는 해당 Domain으로 보호되는 애플리케이션에 로그인할 수 있는지 결정하는 정책이다.<br>

Sign-on Policy는 하나 이상의 Sign-on Rule로 구성되며, 각 Rule은 다음과 같은 조건과 동작을 정의할 수 있다.
- 대상 사용자 또는 그룹
- 관리자 역할 보유 여부
- 제외할 사용자
- Client IP 조건
- 접근 허용 또는 거부
- 재인증 요구 여부
- MFA 요구 여부

> OCI Identity Domain에는 Default Sign-on Policy가 기본 제공된다. 그러나 OCI Console App이 별도의 Sign-on Policy에 연결되어 있는 경우, OCI Console 로그인에는 해당 App에 연결된 Sign-on Policy가 적용된다.<br>
>
> - 최근 OCI Identity Domain에서는 OCI Console 보호를 위한 `Security Policy for OCI Console`이 제공되며, OCI Console App이 해당 정책에 연결되어 있을 수 있다.
> - 이 경우 OCI Console 로그인 제어를 위한 Rule은 `Default Sign-on Policy`가 아니라 `Security Policy for OCI Console`에 추가해야 한다.
> - OCI Console 로그인에 Security Policy for OCI Console이 사용되고 있는 예시

## 4. 사전 준비

### 4.1. 관리자 권한 확인

Sign-on Policy와 Network Perimeter를 관리하려면 적절한 IAM 권한 또는 관리자 역할이 필요하다.

공식 문서 기준으로 Sign-on Policy를 관리하려면 다음 중 하나가 필요하다.
- Administrator 그룹의 멤버
- Identity Domain Administrator 역할
- Security Administrator 역할
- Application Administrator 역할
- manage identity-domains 권한이 부여된 그룹의 멤버

### 4.2. 테스트용 Identity Domain

운영 Domain에 바로 Network Perimeter와 Sign-on Policy를 적용하면 정책 오류로 인해 관리자가 OCI Console에 로그인하지 못할 수 있다.
따라서, 테스트용 Identity Domain을 먼저 생성하여 검증하는 것이 권장된다.

### 4.3. 테스트 사용자 및 그룹

정책 적용 대상을 명확히 하기 위해 테스트 사용자와 테스트 그룹을 생성한다.

## 6. Sign-on Policy
### 6.1. 적용할 Sign-on Policy 선택
Network Perimeter를 생성한 것만으로는 로그인 제어가 적용되지 않는다. 생성한 Network Perimeter를 Sign-on Policy Rule에서 참조해야 한다.<br>

OCI Console 접근 제어에는 다음 중 하나의 Sign-on Policy를 사용한다.
1. Security Policy for OCI Console
2. Default Sign-on Policy
3. 테스트 또는 운영 목적으로 별도 생성한 Custom Sign-on Policy
   ![image-20260610-071551.png](/assets/img/posts/OCI/92815528-5c92-4f7a-b0e8-a178cc9618cc.png)

> 본 문서에서는 Security Policy for OCI Console에 OCI Console App이 연결되어(OCI Console 로그인에 해당 정책이 사용 중) 있으므로, Security Policy for OCI Console 정책에 적용한다.
{: .prompt-info }


### 6.2. 허용 Rule 생성 (1)

먼저 허용된 Network Perimeter에 포함된 IP에서 접근하는 사용자만 Console에 로그인할 수 있도록 Rule을 생성한다.
1. Security → Sign-on policies → Security Policy for OCI Console 클릭
2. Sign-on rules 탭 → Add Sign-on rule 클릭
   ![image-20260610-071828.png](/assets/img/posts/OCI/d303d17f-1f73-4529-864d-2c77b4a9c3c0.png)

3. “Please be careful before making any changes to the **Security Policy for OCI Console** as that could potentially lock you out of system entirely.” → Continue 클릭
   ![image-20260610-072036.png](/assets/img/posts/OCI/04a77b8f-7d0b-416b-832b-b768af212dce.png)

### 6.3. 허용 Rule 생성 (2)

1. Name : \<적절한 허용 룰 이름 입력\><br>
   e.g. allow-console-from-NP
2. Authenticating identity provider : 기본 값 유지
3. Groups : \<해당 룰을 적용할 UserGroup 추가\><br>
   (여기서는 AdminUserGroup을 대상 그룹으로 생성하여 테스트)
   ![image-20260610-073405.png](/assets/img/posts/OCI/b76db761-770b-446f-9ea0-ae6a9da950de.png)

4. Administrator : Off
5. Keep me signed in : Off
6. Exclude users : 비상 관리자 계정 추가<br>
   (해당 Rule을 적용받지 않는 계정)
7. Filter by client IP address
8. Restrict to the following network perimeters: 선택
9. 위에서 생성한 Network Perimeter 선택
10. Actions : Allow access
    ![image-20260610-073603.png](/assets/img/posts/OCI/afe79e62-eb33-4e8e-83cf-73c884448188.png)




> **Administrator 옵션**
> - 관리자 역할 보유 여부를 Rule 조건으로 사용할때 활성화한다.
> - 본 구성에서는 특정 테스트 그룹을 대상으로 Rule을 적용하므로 Administrator 옵션은 Off로 유지한다.
{: .prompt-info }

> **Exclude users 옵션**
> - Exclude users에는 최소 1개의 비상 관리자 계정을 추가하는 것을 권장한다.
> - Sign-on Rule 설정 오류로 인해 모든 관리자가 OCI Console에 로그인하지 못하는 상황을 방지하기 위한 조치이다.
{: .prompt-warning }

11. Prompt for reauthentication : Off (필요 시 On)
12. Prompt for an additional factor : On
13. Any factor / Specified factors only : Any factor
14. Once per session or trusted device / Every time / Custom interval : Every time
    ![image-20260610-074653.png](/assets/img/posts/OCI/756b42ba-ae41-43d0-856c-c4a61569092e.png)


> **Frequency 옵션**
> - Once per session or trusted device : 같은 세션이 유지되거나 신뢰된 디바이스로 인식되는 동안 MFA 재요구를 줄임
> - Every time : 로그인할 때마다 MFA 요구
> - Custom interval : 지정한 시간 간격마다 MFA 재요구
{: .prompt-info }

> **<font style="color: #ff5630;">Prompt for an additional factor : On</font>**
> - 신규 허용 Rule은 기존 MFA for all users Rule보다 먼저 평가되도록 배치할 예정이므로, 해당 Rule 안에서도 MFA를 요구해야 기존 MFA 보안 수준이 유지된다.
{: .prompt-warning }

15. Consent : 체크
16. Justification
17. Other
18. 적정 문구 입력<br>
    (“MFA를 활성화한 상태에서 승인된 회사 IP 범위에서만 OCI 콘솔에 액세스할 수 있도록 네트워크 경계 기반 로그인 규칙을 추가합니다.”)
    ![image-20260610-074916.png](/assets/img/posts/OCI/c6b8d2c7-f5a7-4db0-921c-0725fe6094ea.png)

> **Justification**
>
> - Security Policy for OCI Console에 Sign-on Rule을 추가하면 Oracle 기본 보안 정책 변경에 대한 Consent 항목이 표시된다.
> - 이는 해당 정책을 수정하는 작업이 Oracle Security Defaults 변경으로 간주될 수 있기 때문이다.
>   변경 목적과 영향을 확인한 후 Consent 체크박스를 선택하고 Rule을 추가한다.
> - MFA Configured in External IDP : MFA를 OCI가 아니라 외부 IdP에서 처리하는 경우
> - MFA Configured in Custom Policy : MFA를 별도 Custom Sign-on Policy에서 처리하는 경우
> - Other : 그 외 사유
>
> 본 구성은 OCI Console 접근을 허용된 Network Perimeter로 제한하기 위한 것이므로 Justification은 Other를 선택한다.
{: .prompt-info }

## 7. Rule 순서
### 7.1. 최종 Rule 순서

최종 Rule 순서는 아래와 같다.

| **Priority** | **Rule** | **설명** |
|---------------:|:----------------------------------|:----------------|
| 1 | allow-console-from-NP | 허용 IP + MFA |
| 2 | deny-console-from-other-locations | 허용 IP 외 차단 |
| 3 | MFA for administrators | 기존 Rule 유지 |
| 4 | MFA for all users | 기존 Rule 유지 |


> **순서가 중요한 이유**
> - 기존 MFA for all users가 먼저 평가되면, Network Perimeter 조건을 보기 전에 모든 사용자가 MFA 후 로그인될 수 있다.
{: .prompt-warning }

## 8. 접근 확인
### 8.1. 허용 IP에서의 접근
- 허용된 IP에서는 MFA 수행 후 OCI Console 로그인이 성공한다.

### 8.2. 거부 IP에서의 접근
1. VPN을 해제하거나 모바일 핫스팟 등 허용되지 않은 네트워크로 변경한다.
2. 현재 Public IP가 Network Perimeter에 포함되지 않는지 확인한다.
3. 브라우저 시크릿 창을 열고 OCI Console 로그인 페이지에 접근한다.
4. 동일한 테스트 사용자로 로그인을 시도한다.

> **결과** :ID/PW와 MFA 정보가 올바르더라도, Network Perimeter에 포함되지 않은 IP에서는 OCI Console 로그인이 차단된다.
